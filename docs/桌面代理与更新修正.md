# 1.0.2：让桌面模型列表和更新复用启动器网络

## 针对本次反馈

用户使用 1.0.1，进度条启动器可以联网，但桌面内检查更新和新增模型服务时获取模型列表失败。希望两处沿用启动器已经可用的代理处理，不再另配代理。

本版不要求重新配置代理软件或端口，仍读取原来的 `portable.json`、环境变量和 Windows 系统代理。**保留你原来的 `portable.json`。**

## 已确认的事实与尚不确定的原因

1. **桌面内部更新入口的问题是上一版的设计缺口。** 上一版将官方安装式更新源停用，防止安装器写入宿主，却没有把桌面按钮接到便携更新器。因此其失败不能直接解释成系统代理失效。
2. 官方 0.1.7-rc.2 的获取模型列表由 Host 中的 `dsh-llm-pi-ai` 适配器调用 Node `fetch`，不是界面网页自行请求。
3. 重新下载并检查实际官方发行包后确认：该包已有环境代理安装逻辑。受控测试中，旧版的环境代理逻辑也能够通过便携转接端口访问测试模型服务。**未复现用户端故障，不能断言旧版在用户电脑上完全没有使用代理。**
4. 没有用户端模型服务的具体错误和网络日志，仍不能排除证书信任、代理认证、API Key、Base URL、服务端限制等原因。

## 本版的网络路径

### 获取可用模型

```text
官方 Models 页面
  → 官方 Host 模型发现接口
  → 显式指定代理 dispatcher 的 Node fetch
  → 127.0.0.1 随机端口 + 随机认证口令
  → 启动器同一个系统代理 / PAC / 手动代理解析器
  → 模型服务
```

- 在可信的 Desktop / Host 进程中安装适配器，为普通 Node fetch 显式指定代理 dispatcher，不只依赖某个全局 dispatcher 槽位。
- 处理发行包 Undici 与 Node 内置 fetch 的接口兼容，保留 Request / Response / 流式读取等原生语义。
- 后续全局 dispatcher 被重新安装时，普通模型发现请求仍走显式通路。
- 回环地址直连，避免代理 DSH 自己的本地前后端通信。
- 不向模型服务发送代理口令；HTTPS 仍是 CONNECT 隧道，不解密服务端 TLS。
- 代理失败不自动改走直连，不关闭 TLS 证书校验。
- 默认向运行时传递 `NODE_USE_SYSTEM_CA=1`，让支持该变量的 Node 使用 Windows 系统 CA；用户明确设置的同名变量予以保留。这不保证解决所有企业证书或 Electron 兼容性问题。
- 保留调用者显式提供的安全传输 dispatcher，例如 DNS 固定的 SSRF 防护。此类请求会记录 `explicit-dispatcher`，不会粗暴覆盖其安全控制。
- 此适配仅用于可信的桌面主进程和 Host，不向模型生成的 worker 注入代理凭据，也不是全系统 VPN。

### Electron 的独立会话

- 对默认 Session 和 `electron-updater` Session 显式设置同一个本机代理。
- 上游主流程通过 `app.whenReady()` 进入时，等待这两个 Session 的代理设置完成。
- 为 Electron `net.request` 的独立 `login` 事件补上本机代理认证，而不只监听 `app.on('login')`。
- 本机口令仅回应准确匹配的回环代理主机与端口，不提供给源站或其他代理的认证挑战。
- 新建 Session 同样请求应用代理设置；特殊第三方 Session 或自定义网络实现仍需具体验证。

### 桌面内部“检查更新”

```text
官方桌面菜单 / 设置中的更新动作
  → 私有运行目录中的 nonce + request ID 请求
  → 便携启动器原有的 Go HTTP 客户端
  → 官方固定 HTTPS 更新源
```

- 检查时会显示便携启动器的进度窗口；完成后在官方桌面显示结果。
- 已是官方当前版本时，仅提示，不退出、不安装。
- 发现不同版本后，由用户确认是否安排更新。
- 确认后请求官方正常退出，保留任务中断确认。若取消退出，更新计划保留到本次进程以后正常退出时执行，弹窗中会明确说明。
- 正常退出、剩余子进程结束后，便携启动器接管下载、SHA-512 校验、解包、适配与启动。
- **依然不运行 NSIS 安装器，不恢复原来的安装式自动更新。**
- `Update-DSH.cmd` 仍可独立使用。官方强制版本策略没有被绕过；若强制更新窗口挡住普通菜单，请退出并使用这个独立入口。

## 代码改动范围

除了新增便携模块，本版还对官方 ASAR 中两处入口做了有界改写：

1. 桌面 `lib/main.js`：在唯一的 `openUpdatePrompt` 函数入口委派到便携检查函数，保留原来的调用方和 IPC 来源验证。
2. `dsh-desktop-host/lib/index.js`：在原有 Host 主体执行前安装显式 fetch 代理。入口文件位置和 `import.meta.main` 条件保留。

补丁保存改写前两个文件的 SHA-256 到 `package.json` 的 `dshPortableOriginalSHA256`。新包结构不匹配时停止适配，不盲目替换。不能再把修改后的主入口描述为“字节完全不变的官方入口”。

## 新增诊断：Data/Logs/network.log

记录角色、事件、目的主机/端口、路由类别、HTTP 状态或错误代码；不记录 API Key、代理口令、请求头、请求体、响应体、URL 路径或查询参数。不自动上传日志。

常见记录：

| 记录 | 如何理解 |
| --- | --- |
| `role=host`、`proxy-installed` | Host 的显式代理适配已安装 |
| `fetch-start` + `portable-bridge` | 普通外部请求将通过便携转接端口 |
| `launcher-route` + `upstream-proxy` | 启动器解析为上游代理，不代表远端请求已成功 |
| `resolved-direct` | 系统/PAC/直连例外明确选择直连；不是错误后回退 |
| `tunnel-connected` | 代理 TCP 隧道已建立，尚不能证明远端 TLS、认证或模型接口成功 |
| `fetch-response` + `401/403` | 收到了 HTTP 拒绝，需要结合服务商权限、密钥、地址和响应排查，不能笼统判为没有代理 |
| `fetch-response` + `404` | 常见于 Base URL / 模型列表路径不匹配 |
| `fetch-error` + 证书相关代码 | TLS 信任链问题；不要通过关闭证书校验解决 |
| `authentication-required` / `tunnel-error` / `resolution-error` | 检查代理口令、上游可达性或 PAC 解析 |

内置模型目录可能直接返回本地列表而不联网，这时没有模型请求日志不一定是故障。日志中域名和本地诊断路径仍可能是隐私，分享前请检查。

## 本次验证

- 重新获取官方 0.1.7-rc.2 Windows 发行包，并用它实际捆绑的 `dsh-llm-pi-ai`、`dsh-llm`、Cordis 和 Undici JavaScript 模块进行测试。
- 在 Linux Node 24 中调用真正的 `ctx.llm.discoverModels`，通过本版 Go 转接代理和模拟上游 HTTP 代理，访问带有效测试证书的 HTTPS 模型服务。
- 目的域名使用不可直接解析的 `.invalid` 名称，代理把它映射到测试服务；在模型服务、便携代理和上游代理三个位置统计连接，验证请求确实走过通路。
- 测试中即使主动替换全局 dispatcher，新显式通路仍通过。
- 同时测试旧环境代理逻辑，正常通过，因此没有将用户反馈武断归因到某个未复现的代理缺陷。
- 验证桌面检查更新调用注入的启动器客户端、固定官方 URL、nonce 和 request ID。
- Electron Session 设置、ClientRequest 认证、桌面取消/确认更新由模拟 Electron 测试验证；不是 Windows 桌面实机验证。
- 核心 Go 测试启用 race detector，实际官方 ASAR 补丁测试通过；Win64 EXE 已重新编译，Windows 测试二进制可编译。

完整输出：`proxy-integration-tests.txt`、`proxy-js-tests.txt`。

**限制：本版仍是工程试用版，未在用户的 Windows 电脑、真实代理与真实模型服务上完成复测，也未完成原生 Windows 更新退出再启动的整条 UI 流程验收。**

## 如何升级

1. 从托盘正常退出旧版，备份 `Data`、`Workspace` 和 `portable.json`。
2. 最简方式：将新包中的 `DSH-Portable.exe` 替换到原目录，保留原来的 `tools`、`portable.json`、`Data` 和 `Workspace`。网络设置不必重填。源码和文档可同步替换以保持版本一致。
3. 首次启动会检测旧运行时适配版本，并重新准备官方运行时（核对包约 288 MB），让新的 Host 代理和桌面更新委派真正进入 ASAR；不会删除会话数据。
4. 然后分别测试桌面“检查更新”和模型配置“获取可用模型”。如仍失败，提供操作时间、脱敏后的 `network.log` 对应片段和界面报错；无需提供 API Key。
