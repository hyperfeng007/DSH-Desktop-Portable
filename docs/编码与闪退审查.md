# 编码与闪退专项审查 · 1.0.0 → 1.0.1

审查对象：本会话此前交付的 1.0.0 源码与 Windows EXE。修正版：1.0.1 工程试用版。

## 结论

**不能断言旧版没有闪退隐患。本次确认了源码缺陷和风险，已经做了针对性修正，但没有获得用户历史闪退的日志，因此不能把历史故障归因到某一个缺陷。**

“编码错误导致启动失败”“启动器主动结束子进程”“真正的原生进程崩溃”是不同情况，应分开判断。

## 发现与修正

| 项目 | 1.0.0 中发现的情况 | 判定与 1.0.1 修正 |
| --- | --- | --- |
| Win32 字符串指针生命周期 | `ptr(s)` 辅助函数返回 `uintptr(unsafe.Pointer(wstr(s)))`，随后才传入 Win32 Call | 不符合 Go 对跨系统调用指针保活的要求，存在内存安全风险；本次没有复现该风险造成的实际崩溃。删除这个辅助函数，把转换放到带 `//go:uintptrescapes` 的 Call 参数表达式中 |
| 退出码判断 | 官方窗口就绪后，子进程即使非零退出，也可能进入正常退出提示 | 确认存在逻辑缺陷。修正为非零退出始终报错、保留窗口并记录日志；同时显示十进制和十六进制退出码 |
| 慢启动被强制结束 | 四分钟未得到就绪标记就终止 Job | 确认存在主动结束路径，慢速 U 盘上可能表现得像闪退。改为提示仍在等待，只能由用户取消或其他真实失败路径结束 |
| 用户 JSON 编码 | `json.Unmarshal` 直接读取文件，不处理 BOM | UTF-8 BOM / UTF-16 配置会被拒绝，通常表现为启动失败，而不是原生崩溃。新增 UTF-8、UTF-8 BOM、UTF-16LE/BE BOM 解码，并严格拒绝残缺数据、无效代理项和未知 ANSI/GBK 编码 |
| 环境变量编码 | 先把带 NUL 的整个环境块传给 `UTF16FromString`，必然失败后再逐项拼接 | 旧版回退逻辑并非已经证实的崩溃原因，但绕路且缺少明确验证。改为直接构造排序后的 UTF-16 双 NUL 结尾环境块，显式拒绝非法文本，验证空环境也有两个 NUL |
| 路径长度 | `len(root)` 按 UTF-8 字节限制路径 | 中文路径会被过早判为过长，不等同于崩溃。改为 UTF-16 code unit 计数，保留原来的保守长度上限 |
| 初始化错误日志 | JavaScript 的目录创建和 `app.setPath` 在原来的 try/catch 之外 | 早期异常不一定写入本封装的诊断文件。将完整初始化和原入口导入纳入顶层 await 的错误边界，添加不改变默认异常处理语义的 `uncaughtExceptionMonitor` 记录 |
| 启动器自身异常 | GUI 进程没有专用 Go runtime 崩溃日志；主流程、工作线程缺少恢复边界 | 增加主流程/工作线程 panic 记录，Go runtime crash output 重定向到 U 盘日志；不会承诺能从原生内存损坏、系统强杀或设备拔出中恢复 |
| 就绪标记遗漏 | 只依赖窗口 show / did-finish-load / ready-to-show 事件 | 保留原事件，同时对存活窗口定期复核可见且已加载状态，减少事件时序导致一直未就绪的情况 |

## 原本已采用正确方式的部分

- 子进程使用 `CreateProcessW` 和 `CREATE_UNICODE_ENVIRONMENT`，不是 ANSI 的 `CreateProcessA`。
- 主程序启动与解压过程不通过 cmd.exe 拼接执行，因此不需要用 `chcp 65001` 来修复启动路径。
- 参数用 `windows.EscapeArg` 处理双引号、反斜杠、空参数和空格。
- JavaScript 导入使用 `pathToFileURL`，不是手工拼接 `file://`；这对路径中的 `#`、`%`、中文和空格很重要。
- ASAR 头部长度按实际 UTF-8 字节计算，而不是按字符数计算。
- 1.0.0 最终交付已使用 ESM 顶层 await；本次继续保留。未把开发过程中更早的 CJS 试验入口重新发出。

## 本次测试与证据

### 核心测试

`audit-linux-tests.txt`：Go race detector 下的完整核心回归，包括官方真实 ASAR 适配；补充 BOM / UTF-16 格式、损坏编码拒绝、UTF-16 路径计数和退出分类测试。

### Windows 测试二进制在 Wine 中执行

`audit-windows-wine-tests.txt`：

- 在含 `中文 空格 # & %TEMP% ! ' 𠀀😀` 的目录中复制并启动真实 Windows 测试 EXE。
- 子进程验证工作目录、空参数、包含空格 / 引号 / 尾部反斜杠的参数、中文及非 BMP 字符环境变量，以及 `DSH_HOME`。
- 验证 UTF-8 中文日志能够写入中文文件名。
- 验证真实子进程退出码 23 被保留为错误 `0x00000017`。
- 创建 Win32 控件，在主动触发 Go GC 的循环中反复设置和读取 Unicode 文本。
- 继续验证 Job 终止和代理转接等已有测试。

**环境说明：**第一次 Wine 测试继承了 Linux 的 POSIX/ASCII locale，中文目录创建就失败，尚未进入启动器子进程启动逻辑。保存了原始输出 `audit-wine-posix-locale-initial.txt`。将测试宿主 locale 设置为 `C.UTF-8` 并重启 Wine 服务后，同一测试二进制通过。此调整只针对 Linux/Wine 测试宿主，**不要求 Windows 用户修改系统区域、开启“UTF-8 Beta”或改代码页**，也不构成 Windows 故障归因证据。

### JavaScript 入口模拟测试

`audit-bootstrap-node-tests.txt`：使用 Node 和模拟 Electron API，验证含中文、空格、`#`、`%` 路径的导入，就绪标记，以及目录初始化错误能记录日志并非零退出。

该测试是模拟，不等同于真实 Electron/DSH 完整工作区成功启动。

## 使用建议

先在 `E:\DSH-Portable` 这类短路径测试，以减少上游依赖的兼容性变量；这不是要求中文路径必须改名。

如果再次出现问题，请保留发生时间，并区分：启动器 EXE 自己消失、进度窗口仍在但官方桌面消失、官方桌面已启动后退出。优先检查：

- `Data/Logs/launcher.log`
- `Data/Logs/launcher-crash.log`
- `Data/Logs/bootstrap-error.txt`
- `Data/Logs/desktop.log`
- `Data/Logs/chromium.log`

分享日志前删除 API Key、令牌、代理密码、会话内容和不希望公开的路径。
