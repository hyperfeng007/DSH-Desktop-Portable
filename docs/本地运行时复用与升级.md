# 1.0.4：已有同一官方版本，不重复下载桌面安装包

日期：2026-09-26。Windows 10/11 x64 社区工程试用版。

## 从 1.0.2 / 1.0.3 升级

无需先升到 1.0.3，可以直接升级到本版。

1. 从托盘正常退出 DSH，备份 Data、Workspace、portable.json；建议同时保留旧启动器 EXE 以便必要时回退。
2. 解压本版 ZIP，只将其中的 `DSH-Portable.exe` 替换到原有便携目录。
3. **保留原来的 Runtime、tools、Data、Workspace、portable.json。不要删掉 Runtime，也不要只把 EXE 放到空文件夹。**
4. 启动后先读取小体积的官方更新元数据。若版本号和来源安装包 SHA-512 都与本地记录一致，会显示：

   **本地升级 · 不下载 DSH Desktop**

5. 校验、复制和更新本地适配模块后自动启动 DSH。无需重填 Key、地址或代理。
6. 本版包含 1.0.3 的 HTTP/2/压缩兼容修正，可直接再试 Agnes 的“获取可用模型”。

免下载不等于瞬间完成。安全升级会复制一份现有运行时，U 盘读写和完整性校验需要时间；建议至少留出 **2 GB 空余空间**。程序也会按实际运行时大小计算所需空间。原运行时保留，不会为了省空间先删除它。

## 什么时候下载，什么时候不下载

| 情况 | 行为 |
| --- | --- |
| 正常启动已适配到本版的运行时 | 直接使用本地，不复制、不下载，也不为每次启动检查更新源 |
| 从 1.0.2 / 1.0.3 升级，官方版本号及来源 SHA-512 都相同，校验通过 | 只在本地更新便携适配，不下载桌面安装包 |
| 主动检查更新，官方版本号及来源 SHA-512 均未变化 | 显示已是当前官方版本，不下载 |
| 官方更新源指向不同版本或不同 SHA-512 的构建 | 提示确认后才下载；不会只看版本号就跳过不同的安装包 |
| 现有适配模块被改动、入口校验不一致、ASAR 或外置文件校验失败 | 先询问是否重新下载修复，取消则不下载 |
| 现有 current.json 记录存在但不完整，或其必需文件缺失 | 先询问是否重新下载，取消则不下载 |
| 从 1.0.0 / 1.0.1 直接迁移，或未知封装版本 | 本版未实现可靠的本地迁移，提示后才可重新下载；当前用户已在 1.0.2，不属于此情况 |
| 全新空目录、没有运行时记录 | 按首次准备流程下载官方安装包 |
| 本地复制失败、写入失败、取消或空间不足 | 停止并保留旧运行时，不自动改为下载 |

首次从旧封装升级仍需要访问官方更新元数据来确认版本；**这不是离线升级功能**。元数据访问失败会明确报错，不会把“无法检查”当成“已经是最新版”。之后本版运行时的普通启动可沿用本地，不重新检查版本；主动检查更新才查询更新源。

## 安全升级流程

1. 读取 `Runtime/current.json`，区分“官方构建版本”和“便携适配版本”。不再仅因为便携版本号变化就认定需要下载。
2. 对照官方更新源中的版本号和来源安装包 SHA-512。
3. 验证本地运行时路径、文件类型及大小，拒绝自动复制文件系统链接或特殊文件。
4. 核对 ASAR 的官方版本和便携版本记录；验证四个旧适配模块与已交付 1.0.2 / 1.0.3 的原始内容完全一致；检查移除已知 Host/桌面入口补丁后，原始代码 SHA-256 是否仍与记录一致。
5. 对 ASAR 内部文件和 `app.asar.unpacked` 外置文件，按其现有 SHA-256 完整性记录逐项检查，检查偏移、长度和路径。
6. 在 `Runtime/.local-upgrade-*` 临时目录复制现有运行时。不使用硬链接，不修改原运行时。
7. 只更新副本中的便携模块及 package.json 的适配版本记录；保留官方主程序、已验证的官方入口、原来的外置布局和安装式更新禁用设置。再次校验副本。
8. 将完成的副本移入独立运行时目录。先保存旧指针到 `Runtime/previous.json`，再通过 Windows MoveFileEx 的替换/写穿选项发布新的 `current.json`。
9. 切换前的错误或取消不改变当前指针；临时副本尽力清理。旧目录始终保留。

这里的“校验”是基于本地既有记录和已知适配代码的损坏/未知改动检测，**不是重新取得原始安装包后进行独立发行者认证**，也不能保证检测出所有对本地 EXE/DLL 或校验记录本身的恶意篡改。本地目录若不可信，应选择重新下载验证原始安装包。

运行时准备过程不读写 API Key，也不改 Data、Workspace、portable.json。应用启动后的正常官方数据迁移仍可能发生，因此升级前依旧建议备份数据。

## 失败与回退边界

- 切换前复制/校验/写入失败：旧 `current.json` 和旧运行时保持不动；不会自动转成大包下载。
- 成功切换后：旧目录和 previous.json 保留，可供手动回退。不是“桌面之后发生任何错误都会自动回退”。
- 若手动回退，应先完全退出，并同时使用对应的旧启动器和旧指针；仅恢复旧指针而继续使用新启动器，会再次触发适配迁移。官方数据格式迁移不由本工具自动逆转。
- 断电、设备故障、热拔盘时不能保证临时目录清理或磁盘写入绝对安全。不要在升级过程中拔盘。
- 旧运行时会占用空间；确认新版和数据备份正常之前不要删除。程序不自动清理历史运行时。

## 开发者复现

使用 Go 1.26.1、Node 24.21.0 和从官方包提取的实际模块：

```sh
export DSH_TEST_NODE=/path/to/node24
export DSH_TEST_RUNTIME=/path/to/extracted-asar/dsh
export DSH_TEST_OFFICIAL_ASAR=/path/to/original/resources/app.asar
export DSH_TEST_REUSE_APP=/path/to/full-extracted-official-app
# 大型迁移测试的临时目录至少需要数 GB 空间；不要使用不足 1 GB 的 tmpfs。
export TMPDIR=/path/to/large-test-temp
cd source
go test -race -v ./...
"$DSH_TEST_NODE" --test tests/bootstrap-smoke.mjs tests/electron-network.test.mjs tests/desktop-update.test.mjs
```

Windows 上可单独运行 `go test -v -run TestWindowsExistingLatestOnlyFetchesFeed .`，验证同构建迁移只请求更新源、后续普通启动不联网；这项测试在本交付环境尚未执行。
